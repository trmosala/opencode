Source checkout: `browser-gaps`, `ec2b9b79b87b8680a9d628a0712aa625cd5803ed`.
Production geometry was not changed.

The browser host is the session side panel, not the shared composer DockShell. `session-side-panel.tsx` gives the new-layout `#review-panel` a 10px radius. The classic host has no radius. `browser-panel.tsx` uses `mb-2.5`, measured as a 10 CSS-pixel bottom inset. The shared composer DockShell has a 12px radius but does not contain BrowserPanel.

The native development fixture mounts the actual BrowserPanel and full app styles inside a host with the session side panel's actual classes. Real `browserCommand`, `browserViewport`, and WebContentsView code run in Electron 44.3.0 against an isolated temporary profile and a local green synthetic page. The surrounding magenta background exposes any page pixels outside the host. This is an isolated native fixture, not the complete application shell, installed app, authenticated page, macOS build, or packaged release.

108 geometry cases passed: classic/new x LTR/RTL x 80/100/125% renderer and page zoom x widths 940/620/390 x forced display scale 100/125/200%. JSON reports include measured CSS radius, host rectangle, viewport bounds, native child bounds, devicePixelRatio and Electron's display scale factor. A negative control enlarges the host radius to 24px and verifies that the detector rejects the unchanged 10px inset. Window captures explicitly check for green native child pixels; renderer-only screenshots would not qualify.

24 full native-window images cover both layouts/directions at each display scale, at normal size/zoom and the narrow 125%-zoom case. Twelve additional images crop the same native captures to the lower corners for visual review. `native-*-corners.png` shows the native green page, host inset and magenta exterior. Cropping/resizing only affects the review image, not runtime geometry.
