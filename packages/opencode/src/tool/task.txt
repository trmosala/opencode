Launch a new agent to handle complex, multistep tasks autonomously.

By default, delegate substantial exploration or research, separable implementation, reviews, and test or log analysis to focused subagents. Choose a suitable permitted agent. Keep raw file and log dumps in the subagent's context and request concise results to save parent context.

When using the Task tool, you must specify a subagent_type parameter to select which agent type to use.

When NOT to use the Task tool:
- If you want to read a specific file path, use the Read or Glob tool instead of the Task tool, to find the match more quickly
- If you are searching for a specific class definition like "class Foo", use the Grep tool instead, to find the match more quickly
- If you are searching for code within a specific file or set of 2-3 files, use the Read tool instead of the Task tool, to find the match more quickly
- If you only need a trivial edit or command, use the appropriate tool directly
- If Task is unavailable or no suitable permitted agent exists, use available tools directly
- If the user explicitly asks you not to delegate, do the work directly


Usage notes:
1. Give each subagent a self-contained, bounded task with relevant context, scope, constraints, and expected output. Specify whether it should write code or only research, and how to verify its work, including relevant test commands.
2. Run independent tasks with non-overlapping edits concurrently when useful, using a single message with multiple tool uses. Sequence dependent work after the prerequisite results.
3. Once you have delegated work to an agent, do not duplicate that work yourself or make overlapping edits. Continue with non-overlapping tasks, or wait for the result. For background tasks, you will be notified automatically when the result is ready.
4. Ask for concise findings, file references, changes, verification results, and unresolved risks rather than raw dumps. The parent coordinates and integrates the results and remains responsible for verification and the final answer.
5. When the agent is done, it will return a single message back to you. The result returned by the agent is not visible to the user; summarize the relevant results in your answer. Reuse the returned task_id for related follow-ups to retain the subagent's context instead of starting over.
6. Each agent invocation starts with a fresh context unless you provide task_id to resume the same subagent session, which continues with its previous messages and tool outputs.
7. If you are a delegated worker, normally execute your assigned scope directly. Do not redelegate just to follow this default.
